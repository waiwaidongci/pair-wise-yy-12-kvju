# hxyfront-62011 马术蹄铁修整档案

源提示词编号：6

面向马术俱乐部蹄铁师的修蹄记录前端，支持**马房巡诊断网作业**：断网时蹄形、步态、钉位先记本机，网络恢复后按当天批次编号整批合并。

## 核心机制

- **本机先记**：断网照常登记蹄位检查，按当天批次编号（`B-YYYYMMDD-序号`）暂存 localStorage；同蹄位多次修改沿用同一批次号。
- **整批原子提交**：每条蹄位检查字段缺失即整批拒绝，写入失败不留下半条蹄位检查。
- **原编号重试**：批次写入失败后保持原编号、原内容重试；服务端按批次号幂等，重复到达不产生重复数据。
- **两处同改 LWW**：同一蹄位在本机与对端都改过，保留**现场检查时间（inspectedAt）较晚**的值（不是写入时间）；落败记录仍留痕。
- **复查队列重算**：合并完成后队列按每个蹄位当前保留的新值重新计算复查截止日期。
- **结论失效退回**：已发出的复查结论一旦对应蹄位变化即自动 `issued → returned`；本批自带结论若基于冲突落败值同样退回。
- **冲突状态同源**：马匹列表（四蹄对比）、蹄铁更换历史、复查队列三个视图共用同一冲突状态。

## 分层结构（判定 / 存档 / 界面分开承担）

```
src/core/      判定层：纯函数、无 React、无存储
  types.ts       领域类型
  hoof.ts        蹄位原子性校验、复查日期与队列计算
  merge.ts       批次编号、LWW 冲突判定、结论失效、收敛
  selectors.ts   马匹列表 / 更换历史 / 复查队列派生数据（冲突同源）
  seed.ts        演示种子数据
src/archive/   存档层：localStorage、模拟服务端（断网/故障注入/对端改动）、同步引擎
src/ui/        界面层：React 视图与操作，不含判定规则
```

## 演练路径

1. “切换为断网” → 打开任一蹄位修改后“记入当天批次”（批次显示「本机暂存」）。
2. 在蹄位弹窗里点“对端写入更晚/更早的现场值”，模拟另一台设备的两处同改。
3. 可选“注入一次写入故障”：下一次同步会失败，批次沿用原编号、无半条落盘。
4. “网络恢复 · 按当天批次合并”：观察 LWW 结果、三视图冲突标记、结论退回与队列重算。

## 技术栈

React 19 + Vite + TypeScript，Vitest 判定层 / 同步引擎测试（10 个用例）。
