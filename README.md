# hxyfront-62011 马术蹄铁修整档案

源提示词编号：6 · 端口：62011

面向马术俱乐部蹄铁师的巡诊记录前端：断网时把马匹蹄形、步态、钉位先记在本机，
恢复联网后按当天批次编号合并；同一蹄位两处都修改时保留现场时间较晚的检查值，
复查队列按新值重算；批次写入失败沿用原编号整批重试，已发结论随蹄位变化自动失效退回。

## 技术栈

React + Vite + TypeScript（strict）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62011

## 三层架构（判定 / 存档 / 界面分开承担）

```
src/domain/      判定层：纯类型 + 纯业务规则，无存储、无网络、无 React
  types.ts       实体与状态：蹄位、马匹、检查、批次、复查结论
  rules.ts       批次编号、LWW 合并（按现场时间）、冲突识别、
                 复查队列重算、结论失效退回、蹄铁更换历史、时间线

src/archive/     存档层：本机持久化 + 远端网关（演示用 localStorage 模拟）
  localArchive.ts 本机档案库（断网先落本机）
  remoteGateway.ts 远端：批次整批原子写入，失败整批回滚、原号重试；
                   远端修改流与已接收批次分开存放
  syncEngine.ts  同步编排：推送批次 → 拉取合并 → 队列重算 → 结论失效
  store.ts       仓库 + 状态容器（useArchive 订阅），不含业务规则
  seed.ts        演示数据（含两处冲突、远端-only 蹄位、待退回结论）

src/ui/          界面层：组件只负责展示与交互，判定走 domain，存取走 archive
  SyncBar.tsx        网络状态、批次列表（失败原号重试）、失败模拟
  HorseList.tsx      马匹列表（四蹄状态点 + 冲突徽标）
  InspectionForm.tsx 新增蹄位检查（断网可保存）
  HoofGrid.tsx       左右前后蹄对比 + 蹄位历史
  RecheckQueue.tsx   复查队列（按新值重算，可发结论）
  Conclusions.tsx    复查结论（有效 / 已退回）
  ShoeHistory.tsx    蹄铁更换历史（冲突同步显示）
  selectors.ts       合并视图派生 hook（useCurrents / useQueue / useTimeline）
```

## 关键语义

- **断网暂存**：保存即落本机 localStorage，归入当天批次；失败过的批次沿用原编号。
- **按批次合并**：联网后按批次编号整批推送；同批次幂等，跨天序号顺延。
- **同蹄位冲突（LWW）**：`mergeCurrents` 比较本机与远端最新检查，
  保留 `inspectedAt` 较晚者；值不一致即标记冲突，马匹列表、蹄位对比、
  复查队列、蹄铁历史同步显示冲突状态。
- **原子写入**：`remoteGateway.pushBatch` 一个批次的全部检查在一次事务里落库，
  失败则整批回滚，「不能留下半条蹄位检查」。
- **原号重试**：批次失败后状态置 `failed`、编号不变，重试仍用原编号。
- **队列重算**：`recomputeQueue` 完全由当前蹄位值重算（异常步态 14 天、
  蹄形裂纹 7 天、蹄铁更换 14 天）；旧值消失则条目消失。
- **结论退回**：结论基于发出时的检查 id；合并后该蹄位当前检查不再是它，
  结论即失效退回（`refreshConclusions`）。
- **冲突收敛**：本机值按 LWW 胜出后，远端旧修改被取代，再次合并不再冲突。

## 演示操作

1. 页面顶部可「模拟断网 / 恢复联网」「模拟下次写入失败」「重置演示」。
2. 初始即含一个待同步批次（HORSE-31 左前蹄、HORSE-18 右前蹄两处草稿）。
3. 勾选「模拟下次写入失败」后点「立即同步」→ 批次失败、整批回滚、可原号重试；
   不勾选再次同步即成功。
4. 同步后可见：两处冲突（HORSE-18 右前蹄本机较晚胜、HORSE-31 左前蹄远端较晚胜）、
   复查队列重算（HORSE-27 裂纹进入、HORSE-31 恢复正常移出）、
   HORSE-31 左前蹄结论「已退回」。
